Part 1: What it is and who it's for

My project is a Gaming Backlog Tracker, a web application that allows users to organize and manage their video game collections.

Users will be able to add games they own or want to play, track their progress, and organize games based on their completion status.

The application is intended for gamers who have multiple games and want a simple way to keep track of what they are playing, what they have finished, and what they want to play next.

I want to create a clean and simple interface that makes managing a gaming backlog easy.

Part 2: What can people do with it?

The application will include these features:

★ Add games: Users can add a game with its title, platform, genre, and status.

★ View games: Users can see all games in their collection.

★ Update and delete games: Users can change game information, update completion status, or remove games.

Filter games: Users can filter their collection by "Not Started," "Playing," or "Completed."

Search games: Users can search for a game by its title.

View statistics (extra): Display the total number of games and how many have been completed.

Dark mode (extra): Allow users to switch between light and dark themes.

The first three features are essential. The other features will be added after the basic application is working.

Part 4: Your data

I plan to use MongoDB to store the games.

Collection: games

Field

Type

Required

_id

ObjectId

Yes, generated by MongoDB

title

String

Yes

platform

String

Yes

genre

String

No

status

String

Yes

createdAt

Date

Yes, generated automatically

The status field will have three possible values: "Not Started," "Playing," and "Completed."

Each game will be stored as its own MongoDB document. I do not plan to use nested collections for the initial version.

Example document:

{
  "title": "Elden Ring",
  "platform": "PC",
  "genre": "RPG",
  "status": "Playing"
}

MongoDB will generate the _id, and the backend will set createdAt.
